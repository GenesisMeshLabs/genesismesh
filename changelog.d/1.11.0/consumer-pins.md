### Changed

- **The Interoperability run uses pinned SDK revisions.** It checks out the Go, TypeScript, .NET and Rust SDKs at the revisions in `contract/consumer-pins.json` (a release tag, or a commit on the SDK's `main`), each resolved to its commit on GitHub by `scripts/consumer_pins.py`, instead of the SDK branches named like the core branch. A core pull request is tested against the same SDK code in its own run, in the merge queue and on `main`, so a merge in an SDK repository can no longer turn a core check red. The pins start at 1.10.1. A core change that needs newer SDK behaviour, or changes the conformance vectors the SDKs copy, pins the SDK `main` commits that have it in the same pull request. A pin change runs the Interoperability job ("Jobs a pull request may skip" in `docs/development/testing.md`).

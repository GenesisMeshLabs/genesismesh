### Changed

- **The container jobs test the pinned gateway release, not a gateway built from a branch.** `ci.yml` and `publish-image.yml` used to build the gateway from the branch named like the core branch, from `main`, or from the gateway tag of the core's version; the core 1.10.0 image could not publish until the gateway's version matched. They now pull the gateway release pinned in `contract/consumer-pins.json` (its tag and published image index digest, starting at 1.10.1) by digest, after `cosign verify` checks that the gateway's own release workflow at that tag signed it. `python scripts/consumer_pins.py gateway` resolves the tag on GitHub and prints the image and what it must report. `scripts/container_smoke.py --gateway-version` and `--gateway-revision` check that the image's version and revision labels and its binary report exactly that release; `--version` no longer applies to the gateway image. A core change that needs newer gateway behaviour waits for a gateway release and pins it. A pin change now also runs the container images job.
